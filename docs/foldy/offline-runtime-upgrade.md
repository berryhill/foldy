# Offline release activation

Run Node 24 `node apps/foldy-runtime/dist/upgrade-cli.js <private-request-file>` after stopping the runtime. The request file and its parent must be private and OS-operator-owned. This is local operator authority, not a remotely authenticated owner action.

Request fields (all required): `stateDirectory`, `incumbent: {directory,digest}`, `candidate: {directory,digest}`, `expectedGeneration` (initially 0), `operationId`, `confirmation` (exact instance ID), `dataCompatibility: "foldy-runtime-domain.v1"`, `kind: "upgrade" | "rollback"`. Digests are SHA-256 manifest hashes. Candidate manifests must differ only in runtime-image identity: seed members, identity and protection policy are unchanged. Schema migration is deliberately rejected/not implemented.

The operator and runtime share `runtime.lock`. A running instance excludes offline activation; a crash leaves the lock and needs explicit operator process inspection before removal. Never automatically break it. Snapshot export uses the existing SQLite publication lock and validator. The candidate is verified, privately materialized and reverified; the snapshot and release are flushed before one atomic activation-pointer rename. Existing content, reviews, receipts, owner/grant custody and viewer policy are not replaced. Startup reads the active pointer after acquiring the lock. A failed candidate cannot change the pointer. If the command dies after the rename, inspect `runtime-activation.json` rather than assuming failure/retrying. Generation conflicts fail closed.

Rollback specifies the prior bundle and current generation. It verifies the retained snapshot and refuses rollback if content has changed since activation. This v1 no-migration workflow leaves identical data in place rather than overwriting SQLite or resurrecting old credentials. Keep the original bundle available for rollback.

The existing database must be an operator-owned private regular file, not a symlink or hard link. Schema and stored identity are inspected through immutable read-only SQLite before any writable Domain construction. Stop cleanly and checkpoint before upgrading: pending WAL/recovery journals fail closed rather than being ignored or repaired. Sidecars must satisfy private custody checks. A dangling activation symlink is an error, never an absent pointer. Materialized directory trees are flushed deepest-first, including every intermediate directory and the state parent before activation commit.

## Explicit boundaries

This implements offline release selection consumed by startup, not installation/execution of a different Node runtime binary or provider container image. Image digests are metadata in this local path. No provider, payment, TLS/MCP readiness probe or live deployment was exercised. LifecycleCoordinator still rejects its remote `upgrade` kind; it must not pretend this OS-operator command is a provider lifecycle driver. Owner UI / central Foldy Server must expose an authenticated exact-request approval and stop/execute/restart/readiness orchestration before UI parity can be claimed. Full migration, failed-new-process automatic image rollback and provider image replacement remain integration work.
